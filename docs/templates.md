# Шаблоны выгрузок (DOC-1..DOC-4)

Все документы формируются на сервере. Клиент только скачивает готовый файл:
`Content-Disposition: attachment`, `Cache-Control: no-store`; даты — в часовом
поясе приложения (`settings.timezone`, по умолчанию `Asia/Yekaterinburg`).

## 1. Word-заявка — `backend/templates/ticket.docx`

Файл собирается генератором `backend/scripts/gen-ticket-template.go`
(`go run ./scripts/gen-ticket-template.go` из `backend/`) и коммитится.
Runtime читает его через `go:embed`; замена плейсхолдеров выполняется в
`word/document.xml` без внешнего шаблонизатора. При изменении шаблона
перегенерируйте файл и обновите этот документ.

### Структура `.docx`

| Часть | Назначение |
|---|---|
| `[Content_Types].xml` | типы частей пакета |
| `_rels/.rels` | связи пакета с `word/document.xml` и `docProps` |
| `word/document.xml` | текст заявки и плейсхолдеры |
| `word/styles.xml` | стили `Normal`, `Title`, `Heading1` |
| `word/_rels/document.xml.rels` | связи документа (сейчас пустые) |
| `docProps/core.xml`, `docProps/app.xml` | минимальные свойства документа |

### Плейсхолдеры

| Плейсхолдер | Значение |
|---|---|
| `{{app_name}}` | название приложения из настроек Б7 |
| `{{ticket_id}}` | номер заявки |
| `{{building}}` | здание заявки |
| `{{created_at}}` | дата/время создания (`ДД.ММ.ГГГГ ЧЧ:ММ`) |
| `{{applicant_name}}` | заявитель |
| `{{cabinet}}` | кабинет/помещение |
| `{{problem_type}}` | вид проблемы |
| `{{deadline}}` | дедлайн (`ДД.ММ.ГГГГ`) или `—` |
| `{{status}}` | человекочитаемый статус с учётом настроек |
| `{{executor}}` | исполнитель или `—` |
| `{{description}}` | описание (XML-экранируется, переводы строк схлопываются) |
| `{{comments}}` | блок комментариев: дата, автор, текст, вложения |
| `{{generated_at}}` | дата/время формирования документа |

Проверка: после подстановки в `word/document.xml` не должно оставаться `{{`.
Комментарии вставляются отдельными абзацами; при их отсутствии — «Нет
комментариев».

Маршруты:

- `GET /api/tickets/{id}/export.docx` — USER только своё здание, ADMIN любое;
- `GET /api/public/tickets/{token}/export.docx` — только заявка своего токена.

Имя файла: `ticket_{id}.docx`.

## 2. Excel-статистика — `GET /api/stats/export.xlsx`

Параметры — как у JSON-статистики Б9: `from`, `to`, `user_id`, `building_id`.
Свой отчёт доступен всем, чужой — только ADMIN (иначе `403`); период и фильтры
разбираются общим `stats.ParseQuery`.

Листы:

1. **«Сводка»** — ФИО, логин, период с/по, всего выполнено, выполнено за
   период, среднее время (ч), медиана (ч), в срок (%), просрочено.
2. **«Заявки»** — строки `stats.ExportRow`: №, ID, здание, создана, завершена,
   дедлайн, «в срок», вид проблемы, кабинет, заявитель.

Имя файла: `stat_{login}_{from}_{to}.xlsx`; при отсутствии границы периода
используется `all`.

## 3. Ведомость помещения — `GET /api/warehouses/{id}/inventory.xlsx`

Доступна USER/ADMIN. Состав:

- шапка: приложение (`app_name`), здание, помещение, дата формирования,
  всего единиц;
- таблица: `№`, `Наименование`, `Тип`, `Серийный номер`,
  `Регистрационный номер`, `Примечание`;
- блоки подписей:
  - `Передал: ФИО ______ должность ______ подпись ______ дата ______`
  - `Принял: ФИО ______ должность ______ подпись ______ дата ______`
  - `М.П.`

Ограничение EQ-8: не более 1000 позиций; при большем количестве — `422
VALIDATION_ERROR` с `details.limit`/`details.total`. Имя файла:
`inventory_{id}.xlsx`.

> Примечание: в таблице `equipment` (Б4) нет отдельного поля примечания,
> поэтому колонка присутствует (требование EQ-8), но заполняется пустой.
