# Ручной QA-чеклист и a11y-аудит

Документ для приёмки фронтенда перед Ф11 (Playwright). Проверяется вручную в браузере;
автотесты (`pnpm test -- --run`) покрывают логику, но не отображение, клавиатуру и реальные файлы.

- Версия фронтенда: ветка `main` (после Ф1–Ф10).
- Требования: PLAN.md §3.1–§3.13, NFR-3 (адаптив от 375 px), NFR-6.
- Зона ответственности этого чеклиста: публичный периметр, доска, БЗ, оборудование,
  админка, профиль/push, корзина, статистика, доступность и адаптив.
- Если пункт помечен 🔵, без реального API его **нельзя** принять: MSW отдаёт заглушки.

## 0. Подготовка

```powershell
# из корня репозитория
. .\scripts\dev-env.ps1
cd frontend
pnpm install
pnpm dev          # http://localhost:5173 — MSW включён по умолчанию
```

Демо-доступ в режиме MSW:

| Логин         | Пароль       | Роль / особенность                             |
| ------------- | ------------ | ---------------------------------------------- |
| `admin`       | `admin12345` | ADMIN, здания не привязаны                     |
| `user`        | `user12345`  | USER, «Центральный офис»                       |
| `petrova`     | `user12345`  | USER, «Производственный корпус»                |
| `bez-zdaniya` | `user12345`  | USER без здания — баннер AUTH-9                |
| `novichok`    | `temp12345`  | временный пароль → обязательная смена (AUTH-4) |
| `sidorov`     | `user12345`  | USER «Центрального офиса» (второй сотрудник)   |

Режим с реальным бэкендом (для 🔵):

```powershell
docker compose up -d          # из корня, поднимает MySQL + api + web
# либо против локального API:
$env:VITE_ENABLE_MSW='false'  # vite proxy /api → http://localhost:8080
pnpm dev
```

Обозначения в чеклисте:

- 🟡 **MSW** — проверяется на моках; поведение задано `src/mocks/handlers/*` и `src/mocks/db.ts`.
- 🔵 **API** — нужен реальный бэкенд: бинарные файлы, push-доставка, лимиты, 428/429,
  серверные дедлайны и часовой пояс, транзакции/блокировки.
- ⚪ — одинаково в обоих режимах.

Общие требования к каждому шагу: в консоли нет ошибок, нет `Uncaught`, нет 4xx/5xx
в Network без объяснения, после F5 состояние сохраняется (URL/фильтры/cookie).

### 4.2 Найдено и исправлено в этой ветке

1. **Шапка при 375 px**: текстовый ярлык «Push» занимал место рядом со зданием и аватаром —
   убран, остались иконка + переключатель, доступное имя даёт `aria-label`
   (`src/push/PushHeaderToggle.tsx`).
2. **Таблица оборудования**: чекбоксы выбора строк не имели доступного имени —
   добавлены `aria-label` «Выбрать оборудование «…», INV-…» (`EquipmentTable`).
3. **Дерево оборудования**: не было landmark — добавлен `nav[aria-label="Расположение оборудования"]`.
4. **Пагинация на 375 px**: длинная подпись «Всего единиц: N» + выбор размера страницы
   выезжали за экран — на узких экранах включена компактная пагинация «1 / 5».
5. **Статус push в профиле**: изменения объявляются скринридеру (`aria-live="polite"`).

### 4.3 Найдено, требует исправления (вне зоны этой ветки)

1. **P0 — форма входа `/login` (зона fe-1)**: `react-hook-form` `register` + antd `Input`
   не передаёт значения (проверено тестом в jsdom: после ввода полей форма уходит пустой).
   Риск: вход не работает в браузере после обновления зависимостей. Воспроизведение:
   открыть `/login`, ввести `user/user12345`, отправить — форма валидируется как пустая.
   Рекомендация: перевести на antd `Form` с правилами или на `Controller` (как в
   `PublicTicketCreateModal`), как это сделано для `/change-password` и `/profile`.
2. **Иерархия заголовков (зона fe-1)**: `PageHeader` рендерит `h3`, на страницах нет `h1`
   (публичные страницы — ок, у них `Typography.Title level={1}`). Рекомендация: добавить
   `level` в `PageHeader` и использовать `h1` для заголовка страницы.
3. **Переход по маршрутам не переводит фокус** (app shell): после SPA-навигации фокус
   остаётся в меню; скринридер не узнаёт о смене экрана. Рекомендация: фокус на `main`
   или на `h1` при смене `location.pathname` + `aria-live` анонс.
4. **Нет skip-link** «Перейти к содержимому» в `AppLayout`/`PublicLayout` (есть класс
   `.sr-only`, но ссылки нет).
5. **Контраст (тема/палитра статусов)** — см. 4.5.

## 7. Что нельзя принять без реального API (🔵)

1. **Word/Excel**: содержимое, имя файла, `Content-Disposition`, `Cache-Control: no-store`,
   лимит 1000 позиций (`422`), шапка/подписи ведомости, даты в `timezone`.
2. **Web Push**: реальная доставка через push-сервис (VAPID-ключи бэкенда), клик по
   уведомлению (фокус вкладки в прод-сборке), схлопывание по `tag`, недоступность
   без HTTPS. MSW отдаёт демо-ключ и не умеет отправлять push.
3. **Серверные вычисления**: дедлайн по рабочему календарю и праздникам, `is_overdue`,
   границы суток в `timezone`, автоочистка корзины 90 дней, напоминания.
4. **Безопасность**: refresh-ротация и отзыв токенов, `428` при временном пароле,
   rate limit `429`, блокировка пользователя «со следующего запроса», `404` вместо `403`
   для чужих заявок, санитизация HTML на бэкенде, права на файлы.
5. **Файлы**: загрузка фото/видео (multipart, лимиты, прогресс), range-запросы видео,
   выдача `/api/files/{id}` под проверкой прав.
6. **Транзакционность**: массовое перемещение (блокировки, откат при отсутствии id),
   восстановление из корзины (конфликты номеров, живой родитель БЗ).
7. **Объёмы**: 10 000 заявок / 2 000 оборудования / 500 узлов БЗ — p95 ≤ 300 мс,
   серверная пагинация под нагрузкой.
8. **Интеграция nginx/Docker**: SPA fallback, прокси `/api`, `client_max_body_size 210m`,
   кэширование хешированных ассетов и `no-store` для `/sw.js`.

Заполняется принимающим:

| Блок                                                    | Результат        | Замечания            |
| ------------------------------------------------------- | ---------------- | -------------------- |
| Аноним: выбор здания, cookie, создание, `/t/{token}`    | ☐ ок ☐ замечания |                      |
| USER: вход, заявки, БЗ, оборудование, профиль/push      | ☐ ок ☐ замечания |                      |
| ADMIN: заявки, пользователи, справочники, настройки     | ☐ ок ☐ замечания |                      |
| ADMIN: здания/склады, БЗ-модерация, корзина, статистика | ☐ ок ☐ замечания |                      |
| Клавиатура/скринридер                                   | ☐ ок ☐ замечания | P0: `/login` (4.3.1) |
| Адаптив 375 px                                          | ☐ ок ☐ замечания |                      |
| Push (реальный)                                         | ☐ ок ☐ замечания | 🔵                   |

Блокеры для Ф11: форма входа `/login` (4.3.1), контраст палитры статусов по умолчанию (4.4),
фокус при SPA-навигации и skip-link (4.3.3–4.3.4) — рекомендованы к исправлению
до e2e/lighthouse, т.к. они влияют на сценарии входа и axe-проверки.
